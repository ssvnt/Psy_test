# Исправленное письмо о детском отчёте

Оператор указывает номер оплаченной сессии при запуске `python3 apply.py НОМЕР` на сервере Laravel. Адрес берётся из заказа и сверяется с регистрацией, покупателем и отправленным событием report_ready. В почту уходят три временные подписанные ссылки. Каждое открытие заново проверяет оплату, адрес и версию согласованного отчёта. Для HTML и PDF используются опубликованные байты основного генератора или клиентская копия согласованного R27. У R27 дополнительно сверяются решение владельца, замечания QA, срок публикации и контрольные суммы файлов.

Ссылки ведут к отчёту, PDF и календарю. Форма использует существующий сервис записи, проверку CSRF и явное согласие на передачу отчёта специалисту. Переход по ссылке не бронирует время. Перед отправкой выполняются три HTTPS GET без cookies и с запретом переходов по редиректам. HTML и PDF должны совпасть с утверждёнными побайтово. На странице записи должны быть свободное время или подтверждённая консультация.

Установка добавляет один маршрут перед общим маршрутом Vue и четыре файла Laravel. Для действующего кеша маршрутов сначала формируется новый кеш в отдельном файле. Предыдущие файлы маршрутов сохраняются в storage/app/dz-ready-mail-backups. При ошибке до SMTP попытки установщик откатывает собственное изменение маршрутов, если с момента установки файл не менялся. Для ручной сверки используется каталог storage/app/dz-ready-mail-corrections-v1. Квитанция сохраняет состояние попытки и хеш почтового идентификатора.

- `SMTP_ACCEPTED REPORT_HTML_OK PDF_OK BOOKING_OK` — почтовый сервер принял исправленное письмо после успешной проверки ссылок.
- `ALREADY_ACCEPTED_BY_SMTP` — исправленное письмо уже принято. Повторного отправления нет.
- `NO_BOOKABLE_TIME_OR_CONFIRMED_APPOINTMENT` — требуется проверить расписание или предыдущую запись.
- `DELIVERY_UNCERTAIN_CHECK_MAIL_LOG_BEFORE_RETRY` — результат SMTP требует сверки с журналом почтового сервера. Не удаляйте квитанцию для повторной попытки.
- Для остальных `CORRECTION_STOPPED` укажите код при обращении к разработчику. В диагностике нет персональных ссылок.

В локальном сквозном тесте использовались SQLite, HTTPS и тестовый SMTP. Проверены открытие всех трёх ссылок новым клиентом, запись, защита формы, повтор отправки и повтор брони, отзыв доступа после отмены оплаты, повреждённые данные QA и подпись ссылки. Выполнены установка с действующим кешем маршрутов и установка без кеша. На основном генераторе проверены байты утверждённого HTML и PDF, адрес и отзыв публикации в штатном тесте Laravel.
