# Добрый Жук · исходная версия для интеграции и QA

В evidence/ лежат три полученных от владельца файла RC5 в исходном виде. Оба JSON описывают пути, признаки проверки и контрольные суммы. ZIP содержит анализатор и его тесты. Отчёт RC5 воспроизведён побайтово на приватной копии.

Для восстановления снимка нужны два приватных архива от 8 ноября и манифест от 9 ноября. prepare_qa.py проверяет контрольные суммы архивов, манифеста, всех 1 800 файлов и трёх вложений. Скрипт сверяет 348 записей между отчётами и снимком. Итог содержит 1 196 файлов Laravel/Vue в source/site и 70 файлов оркестраторов в source/opt. Из исходного дерева исключены 534 файла сборок.

## Восстановление

Запускайте на Linux с Python 3.9+ из корня клона. Поместите исходные архивы и манифест в каталог, доступный только команде. Укажите новую директорию вне Git и рабочего сайта. В примере обе директории находятся в домашнем каталоге разработчика.

```bash
review=review/server-baseline-rc5-20261110
qa="$HOME/dz-qa-20261110"
python3 "$review/prepare_qa.py" "$HOME/dz-private-input" "$qa"
python3 -B review/gardner-rc1-20261109/builder/stage_candidate.py \
  --check --site "$qa/source/site" --r27 "$qa/source/opt/dz-gardner-r27-live"
```

Приватные входные файлы:

- DZ_SITE_SOURCE_20261108T225027Z.tar.gz
- DZ_ORCHESTRATOR_SOURCE_20261108T225027Z.tar.gz
- DZ_SOURCE_MANIFEST_20261109.json

Для разработки используйте отдельную копию восстановленного дерева. Исходные архивы содержат исторические привязки платежей и ресурсы, требующие проверки прав. При работе с Orders и Prices сохраняйте ранее выданный доступ покупателя. Сведения о реальных заказах остаются в приватном контуре.

RC1 сопоставлен с 13 файлами снимка и добавляет 4 файла в отдельный кандидат. Ветки RC2–RC4 содержат разработки для последующей интеграции. В протоколе QA отдельно фиксируются результаты исходной версии и кандидата. Публикация материалов в GitHub не запускает выкладку.

## Сборка проверенного кандидата

prepare_candidate.py восстанавливает исходники, формирует RC1 через его штатный builder, добавляет файлы из overlay по контрольным суммам candidate-files.json и накладывает candidate.patch. Сборка требует PHP CLI, Python и Git. Создайте новую приватную директорию. Повторная независимая сборка до изменения примеров дала все 1 274 файла кандидата с совпадающим содержимым.

```bash
review=review/server-baseline-rc5-20261110
candidate="$HOME/dz-rc1-qa"
python3 -B "$review/prepare_candidate.py" "$HOME/dz-private-input" "$candidate"
cd "$candidate/source/site"
mkdir -p bootstrap/cache storage/app/private storage/app/public storage/framework/cache/data storage/framework/sessions storage/framework/views storage/logs
composer install --no-interaction --prefer-dist
npm ci --no-audit --no-fund
npm run build
python3 -m pip install --target tmp/gardner-20261030-python -r resources/gardner/v2/text-quality/requirements.txt
```

Запускайте PHPUnit на отдельном стенде с заблокированным исходящим трафиком, SQLite в памяти, тестовым ключом из phpunit.xml и без производственного .env. Для прогона использован PHP 8.4.24 с расширениями SQLite, mbstring, DOM, XML, XMLWriter, cURL, ZIP и GD.

```bash
APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=:memory: MAIL_MAILER=array \
  CACHE_STORE=array SESSION_DRIVER=array QUEUE_CONNECTION=sync \
  php -d memory_limit=1G vendor/bin/phpunit --colors=never --log-junit /tmp/dz-private-junit.xml
```

## Интеграционные исправления и проверка

В тестах оплаченного Гарднера подтверждена выдача HTML/PDF владельцу после проверки содержимого, включая сокращённый профиль. В случае пустого списка наблюдений брендированный шаблон использует пояснение из предыдущего шаблона PDF. Пустая итоговая группа не выводится. Все девять разделов сохраняются. Ответы теста и расчёт шкал не менялись.

В интеграционном сценарии владелец сессии может оформить заказ по сохранённому ключу, а затем подтвердить email. Переход по клиентскому редиректу не подтверждает оплату. При отсутствии валюты операция требует идентификатора проверенного рублёвого договора в настройках или полного совпадения с ранее сверенной исторической квитанцией. Проверки суммы, операции, товара, получателя и владельца заказа сохраняются. До открытия продаж на стенде требуется сверить фактическую конфигурацию договора. В PostgreSQL 17 воспроизведена отдельная ошибка после создания платёжной ссылки: поля цены и скидки в старой таблице сессий принимают целые рубли. Теперь формат этих полей проверяется до обращения к банку, сумма заказа сохраняется в копейках.

При неопределённом биллинге и повреждённом JSON повторное чтение возвращает состояние сверки. Для учтённого, но усечённого ответа при отключённом платном повторе сохраняется причина незавершённости. Проверены отсутствие повторного списания на имитации провайдера и сохранение ранее подтверждённых расходов.

Список консультаций и запись проверяют один и тот же календарь специалиста. Старый слот за пределами расписания скрыт из списка. Проверены 20-минутные интервалы в среду и субботу по Иркутску, повтор и конфликт брони, отмена, возврат, согласие на доступ к отчёту. В сквозном сценарии покупателю уходит тестовое письмо о записи, специалисту — ровно один вызов MAX после фиксации брони. Повтор того же запроса не дублирует вызов. Сервисы банка, провайдера, SMTP и MAX в сценариях имитировались.

На локальной чистой PostgreSQL 17.11 выполнены 59 миграций. На этой же БД проверен путь от нового заказа с промокодом до подтверждения оплаты, повторной банковской проверки, бронирования, повтора записи и отмены. Для повтора используйте пустую локальную БД dz_qa, запустите миграции и из каталога восстановленного Laravel выполните:

```bash
APP_ENV=testing DB_CONNECTION=pgsql DB_HOST=127.0.0.1 DB_DATABASE=dz_qa \
  php /path/to/review/server-baseline-rc5-20261110/tests/pgsql-smoke.php
```

Для запуска укажите подходящие для локальной БД DB_PORT, DB_USERNAME, DB_PASSWORD и тестовый APP_KEY. Скрипт проверяет окружение и пустоту таблиц приложения, подменяет банк и почту, выполняет операции в транзакции и откатывает данные. Автоинкрементные идентификаторы в тестовой базе могут увеличиться.
