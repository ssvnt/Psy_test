# Добрый Жук · исходная версия для интеграции и QA

В evidence/ лежат три полученных от владельца файла RC5 в исходном виде. Оба JSON описывают пути, признаки проверки и контрольные суммы. ZIP содержит анализатор и его тесты. Отчёт RC5 воспроизведён побайтово на приватной копии.

Для восстановления снимка нужны два приватных архива от 8 ноября и манифест от 9 ноября. prepare_qa.py проверяет контрольные суммы архивов, манифеста, всех 1 800 файлов и трёх вложений. Скрипт сверяет 348 записей между отчётами и снимком. Итог содержит 1 196 файлов Laravel/Vue в source/site и 70 файлов оркестраторов в source/opt. Из исходного дерева исключены 534 файла сборок.

## Восстановление

Запускайте на Linux с Python 3.9+ из корня клона. Поместите исходные архивы и манифест в каталог, доступный только команде. Укажите новую директорию вне Git и рабочего сайта. В примере обе директории находятся в домашнем каталоге разработчика.

```bash
review=review/server-baseline-rc5-20261110
qa="$HOME/dz-qa-20261110"
python3 "$review/prepare_qa.py" "$HOME/dz-private-input" "$qa"
python3 -B review/gardner-rc1-20261109/builder/stage_candidate.py \
  --check --site "$qa/source/site" --r27 "$qa/source/opt/dz-gardner-r27-live"
```

Приватные входные файлы:

- DZ_SITE_SOURCE_20261108T225027Z.tar.gz
- DZ_ORCHESTRATOR_SOURCE_20261108T225027Z.tar.gz
- DZ_SOURCE_MANIFEST_20261109.json

Для разработки используйте отдельную копию восстановленного дерева. Исходные архивы содержат исторические привязки платежей и ресурсы, требующие проверки прав. При работе с Orders и Prices сохраняйте ранее выданный доступ покупателя. Сведения о реальных заказах остаются в приватном контуре.

RC1 сопоставлен с 13 файлами снимка и добавляет 4 файла в отдельный кандидат. Ветки RC2–RC4 содержат разработки для последующей интеграции. В протоколе QA отдельно фиксируются результаты исходной версии и кандидата. Публикация материалов в GitHub не запускает выкладку.

## Сборка проверенного кандидата

prepare_candidate.py восстанавливает исходники, формирует RC1 через его штатный builder, добавляет четыре файла из проверенных источников и накладывает candidate.patch. Сборка требует PHP CLI, Python и Git. Создайте новую приватную директорию. Повторная независимая сборка дала все 1 274 файла кандидата с совпадающим содержимым.

```bash
review=review/server-baseline-rc5-20261110
candidate="$HOME/dz-rc1-qa"
python3 -B "$review/prepare_candidate.py" "$HOME/dz-private-input" "$candidate"
cd "$candidate/source/site"
mkdir -p bootstrap/cache storage/app/private storage/app/public storage/framework/cache/data storage/framework/sessions storage/framework/views storage/logs
composer install --no-interaction --prefer-dist
npm ci --no-audit --no-fund
npm run build
python3 -m pip install --target tmp/gardner-20261030-python -r resources/gardner/v2/text-quality/requirements.txt
```

Запускайте PHPUnit на отдельном стенде с заблокированным исходящим трафиком, SQLite в памяти, тестовым ключом из phpunit.xml и без производственного .env. Для прогона использован PHP 8.4.24 с расширениями SQLite, mbstring, DOM, XML, XMLWriter, cURL, ZIP и GD.

```bash
APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=:memory: MAIL_MAILER=array \
  CACHE_STORE=array SESSION_DRIVER=array QUEUE_CONNECTION=sync \
  php -d memory_limit=1G vendor/bin/phpunit --colors=never --log-junit /tmp/dz-private-junit.xml
```

## Восстановленные компоненты и исправления

- Два файла LICENSE взяты из закреплённых в SOURCE_MANIFEST.json коммитов humanizer-ru и pishi-normalno. Хэши совпали. С зависимостями из requirements.txt обе проверки текста выполняются на стенде.
- TeenReportPrice и TochkaOperationGuard восстановлены из DZ_Payment_Stage3_SafeFix_20261103.zip. SHA-256 пакета 2f1a45d0674ff17f2b3ed3ee7f83c6543fb28293adbb875d841e916f3dc7bb64. Контрольные суммы обоих классов совпали с manifest.json пакета. Его автономная проверка цены и банковского ответа прошла.
- Для новой подростковой сессии контроллер использует утверждённую цену 3 490 ₽ из TeenReportPrice. Ранее он читал изменяемую настройку с резервной ценой 3 500 ₽. Промокод, форма и сохранение цены теперь опираются на утверждённый тариф. Изменение затрагивает создание новой сессии. В тесте промокодов сохранено заведомо отличающееся значение настройки, чтобы обнаружить возврат к прежней логике.
- Исправлена настройка двух наборов тестов checkout с Mail::fake(). Тест отказа провайдера теперь получает актуальные зависимости через Laravel. Производственные флаги этими правками не включаются.

## Что должно пройти до релиза

1. Уточнить с действующей логикой заказа, когда требуется подтверждение email и при каких доказательствах допустим ответ банка без валюты. В двух сценариях проверки получили HTTP 200 при ожидаемом HTTP 409. Сохранить права существующих оплаченных клиентов при исправлении.
2. Устранить ошибку BRANDED_RENDERER_FINAL_GROUP_observe. Проверить блок наблюдений на независимом и сжатом профиле, генерацию HTML/PDF и доступ владельца. Сейчас несколько маршрутов с генерацией отчёта прерываются в рендерере.
3. Проверить бронирование и возврат, занятые слоты, права специалиста, рабочие окна и часовой пояс. Для спорных HTTP 409/422 воспроизвести стабильные даты на тестовом календаре. Отдельно сверить классификацию неизвестного биллинга, усечённого ответа и повтора.
4. Разобрать обязательные материалы оператора и пять пропущенных тестов. Подключить RC2–RC4 через реальные обработчики Laravel, проверить дедупликацию писем, MAX, восстановление воркера и выдачу ранее оплаченного отчёта. Оригинальный пакет писем содержит 10 пар HTML/TXT для двух продуктов с двухступенчатым напоминанием, а RC3–RC4 моделируют одно напоминание через 12 часов. Расписание требует сверки перед включением рассылки.
5. На свежей копии production PostgreSQL с обезличенными данными повторить пользовательские маршруты, проверить сборку, очереди, ранее выданные ссылки и откат. Перед переключением проверить расхождение текущего сервера и снимка. Статус этой ветки — NO-GO для production.
