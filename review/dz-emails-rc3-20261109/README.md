## Четыре события для каждого продукта

| Событие | Триггер | Ключевой предохранитель |
|---|---|---|
| `test_completed_offer` | после завершения теста, при согласии на рекламные сообщения | только новый completion, нет заказа, адрес привязан |
| `unpaid_12h` | ровно не раньше `completed_at + 43 200 секунд` | повторная проверка отсутствия оплаты **и любого ожидающего банковского заказа** непосредственно перед отправкой |
| `payment_confirmed` | авторитетное подтверждение банка | сверка order_id / session / amount / RUB, не путать банковский редирект с оплатой; сервисное письмо независимо от readiness генератора |
| `report_ready` | опубликованные и проверенные HTML/PDF | QA/pass, approval, hashes, доступ, ссылки на полный отчёт и консультацию; отсутствующие слоты не задерживают письмо |

`payment_confirmed` имеет **две копии** текста: `24h` только при утверждённом и исполняемом SLA, `status_only` — при отсутствии подтверждённого SLA. Без маркетингового согласия сервисные письма после подтверждённой оплаты допустимы только при наличии надлежащего законного основания и корректно привязанного адреса — фактическая правовая проверка требуется отдельно.

## Файлы

- `src/MailJourneyPolicy.php`: проверяемая, без побочных эффектов, модель допуска события и детерминированного event key; ни один метод не отправляет почту и не подключается к БД.
- `src/MailPreviewRenderer.php`: HTML+TXT preview с обязательным HTTPS и проверкой домена, экранированием пользовательского текста.
- `drafts/PROPOSED_COPY_NOT_VERIFIED_AGAINST_UPLOADED_ZIP.json`: 8 предложенных текстов и 2 нейтральных сервисных варианта **не из оригинального ZIP**.
- `tests/`: офлайн-проверки двух продуктов, 12-часового срока, отмены после оплаты, QA, SLA, URL, XSS и маркетингового согласия.
- `artifacts/previews/`: 20 HTML/TXT превью по фейковому домену `example.test`, не отправлять клиентам.
- `docs/`: схема безопасного подключения к существующему Laravel, матрица QA, список блокеров публикации.

## Никаких конфликтов с RC1/RC2

В RC1 уже есть `GardnerFreeOfferMail`, native `GardnerCommerce/Outbox`, `GardnerCommerceTick`; в teen — отдельные `TestInterpretationPaymentMail`/`TeenApprovedMailDelivery` по исторической трассе. Этот пакет **не создаёт вторых слушателей этих событий**, не правит существующие Mailable/Blade, не отправляет письмо после оплаты второй раз. Для реальной интеграции нужен канонический `event_key` и один отправитель на этап, с миграциями и E2E в изолированном Laravel.

**Особый риск:** у неоплатившего клиента восстановление ключа доступа на другом устройстве в старом Gardner потоке может быть недоступно. Прежде чем активировать маркетинговую email-кнопку, нужна проверенная безопасная схема восстановления, иначе письмо приведёт на закрытую страницу.
