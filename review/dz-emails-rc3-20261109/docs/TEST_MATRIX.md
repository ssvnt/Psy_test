# RC3 — матрица тестирования (отдельно офлайн и в будущем Laravel)

## Уже выполненные независимые офлайн-тесты

`php tests/test_policy.php`: 40 детерминированных сценариев для двух продуктов, включая consent, подписку/отписку, anti-old-backfill, 12 часов, existing pending, `creating`, `creation_unknown`, сумму, RUB, SLA и publication QA. `php tests/test_renderer.php`: 11 кейсов HTML/TXT preview, домена, HTTPS, XSS. `python -m unittest discover -s tests -p test_copy.py`: 6 проверок структуры 8 вариантов и 2 нейтральных подтверждений. **Итого 57 офлайн-контрактов PASS.** База, Laravel, bank, SMTP и MAX не затронуты.

## Реальное E2E на изолированном staging — всё ещё REQUIRED

1. Children: завершение теста → единственный consented email → кликабельный результат; проверить 375/390 px и другой браузер.
2. Teen: завершение теста → единственное существующее или новое письмо без дубля старого `TestInterpretationPaymentMail`.
3. Отсутствие маркетингового согласия: ноль CTA/followup, сервисная доступность результатов сохраняется.
4. Отписка: реальный POST/GET с защитой и аудитом, отмена ранее запланированного 12h.
5. 12 часов минус секунда: не отправлять; ровно 12 часов: один intent; повторный cron 10 раз: один intent.
6. Оплата между постановкой `unpaid_12h` и SMTP send: письмо отменяется после повторного DB check.
7. `pending`, `creating`, `creation_unknown`: остановка followup до банковской сверки; никаких повторных счетов.
8. Непроверенная/неверная сумма, валюта, operationId, session mismatch: платёжное письмо не отправляется.
9. Bank APPROVED + browser closed: сервисное письмо создаётся автоматически из durable event.
10. Payment email без 24h SLA: нейтральная копия доставляется, срок не обещается. С подтверждённым SLA: указывается 24 часа.
11. Отчёт с quality FAIL / private preview: никаких ready emails и ссылок.
12. QA PASS, owner APPROVED, точные HTML/PDF SHA: одна ready mail, две работающие кнопки.
13. Изменена версия отчёта после письма: новый event key только если новая версия действительно утверждена и опубликована.
14. Report опубликован, консультации нет слотов: письмо готовности отправляется, кабинет даёт маршрут ожидания/запроса.
15. Клиент уже записался на консультацию: кнопка ведёт на действующую запись, не создаёт вторую.
16. SMTP принимает письмо и падает до DB commit: `delivery_unknown`, нет слепого автоматического повтора.
17. SMTP 429/503 или отключён: очередь не теряется; retries только по проверенной политике.
18. Редирект банка и дубликат callback: один payment event, без ложного подтверждения по редиректу.
19. Два клиента с совпадающим session numeric id в разных продуктах: уникальные event key и строгий доступ.
20. Ранее опубликованные teen 102 / Gardner 105 / оплаченные incident 104/106: нет массовых писем и изменений прав.
21. Нет связанного email / не подтверждён адрес / unsubscribe: персональные результаты в письме никогда не раскрываются.
22. Подавление писем не мешает завершать бесплатный тест, готовить отчёт и записываться на консультацию.
23. Проигрывание существующих событий Outbox/Teen sender: не появляются два письма на одно действие.
24. Даты через полночь и переход часовых поясов: 12 часов вычисляются от точного UTC timestamp, не от «следующего дня» календаря.
25. Валидация подлинных файлов `DZ-Emails(1).zip`, сравнение каждого HTML/TXT с предварительно согласованным оригиналом и дизайном — BLOCKED, до получения читаемых байтов.

**Релизное условие:** 25/25 E2E PASS + юридические согласия/отписка + approved copy + SLA + sandbox recovery + legacy regression. До этого `NO PRODUCTION SEND`.
