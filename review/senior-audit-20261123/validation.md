## Что именно падало до исправлений

- Календарь возвращал пустой массив вместо id допустимого слота.
- Сохранение teen meeting URL возвращало 500 (`email on null`).
- Неизвестный web URL возвращал 200 вместо 404.
- Собранный кандидат не содержал ReadyMailAccess и маршрут исправленных писем.
- Старый payment receipt давал `bank_verified=true` для другой текущей операции.
- Recorder успевал записать чужую операцию, вместо отказа до insert.
- R27 reader возвращал отчёт с `blocked=1` и acknowledgement.
- Первое ready-письмо открывало Vue shell вместо утверждённых байтов отчёта.
- Браузер устанавливал timer после unmount, создавал 5 status-запросов вместо 2 и повторно читал детский заказ после ухода.
- Production bundle не показывал контрольный раздел отчёта. После выделения секций, но до sanitizer, были обнаружены исполняемый атрибут и javascript URL. Обе части исправления проверены вместе.

В ходе проверки собственного патча общий набор обнаружил изменение 404→405 для неизвестного POST API. Fallback ограничен web-путями; старый тест оставлен без правок. После этого повторён весь набор. В промежуточном запуске также был дополнительный skip Stage 210 из-за отсутствующей переменной каталога банков; итоговый прогон задаёт оба каталога, остаются только три прежних skip.

У владельца запрошена конкретная ссылка, если речь о другом репозитории/запуске.

Описание старого PR #1 упоминает отказ registry 403 и невозможность запуска браузерного теста до сборки; это не предоставленный лог Actions и не доказанная ошибка текущего кода. Эти сообщения не смешиваются с результатами настоящего локального прогона.

У локального повторного сборщика была одна ошибка окружения: RC1 precheck запускает `php -l`, а первый вызов не получил путь к подготовленному PHP. Повтор с PHP 8.4 в PATH прошёл. Это отдельный локальный сбой запуска, не ошибка GitHub Actions и не необходимость править зависимости или рабочий сервер.

## Граница проверки

Окружение: PHP 8.4.24 / PHPUnit 11.5.55, Node 24.22.3, Python 3.12.14, Chromium Headless Shell 156.0.8078.79, SQLite в памяти. Для PHPUnit системным фильтром запрещены IPv4/IPv6-сокеты; тесты используют синтетические данные, fake bank/model/MAX и Mail::fake/array. Браузер ограничен локальным origin, API новых сценариев подменён.

В этом прогоне не проводились реальная оплата, платные вызовы модели, отправка клиентам, нагрузочный тест, новая PostgreSQL-конкурентная проверка или обновление рабочего сервера. Полный UI-аудит каждого возможного пути и подтверждение production безотказности не заявляются. Новый экран 404 проверен на 390/1440 px; состояние раскрытия отчёта доступно через aria-expanded/aria-controls; существующие примеры проверены на горизонтальное переполнение. Остальная a11y/assistive-technology приёмка требует отдельного прохода.

Десять воспроизведённых дефектов закрыты тестами и патчами. Решение по production остаётся NO-GO по [неподключённым требованиям](requirements.md).
