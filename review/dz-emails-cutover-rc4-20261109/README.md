# Добрый Жук · RC4 — замена почтового маршрута (Laravel / review only)

**9 ноября 2026 года.** Этот комплект заменяет *предлагаемую* RC3-модель превью на реализованный, но **не подключённый к production**, outbox и почтовый цикл. База: `review/dz-emails-rc3-20261109`. Основная ветка GitHub `ssvnt/Psy_test/main` — **исторический Next.js**, а работающий сайт `/var/www/bribon` — Laravel/Vue. Поэтому новые PHP-файлы остаются под `review/.../laravel/`, не конфликтуют с Next.js и не деплоятся автоматически.

## Что реально написано

- Восемь русских шаблонов: `gardner / teen` × `test_completed_offer / unpaid_12h / payment_confirmed / report_ready`. Для письма после оплаты есть нейтральный вариант, если подтверждённое SLA 24 часа отсутствует.
- **Единая последовательность** событий с фиксированными ключами и повторной проверкой фактов прямо перед отправкой; не создаёт заказы и не вызывает модели.
- **+12 часов** после сохранённого `completed_at` (UTC), а не после времени регистрации, оплаты либо последнего `updated_at`.
- Маркетинговые письма требуют отдельного доказанного согласия и подписанной ссылки отписки. `GET` показывает форму, только подписанный `POST` отключает маркетинг; системные письма сохраняются.
- Письмо о подтверждении оплаты только после bank confirmation, привязанной к session/operation/amount/RUB. `bank verified` из клиентского редиректа не допускается.
- Письмо `report_ready` только при фактической проверке approved HTML/PDF, QA и защищённых маршрутов. Подростковый и детский отчёт проверяются соответствующими старыми доменными сервисами.
- SMTP-транспорт не используется из тестов. Успех помечается `accepted_by_mailer`, а не `delivered`; неизвестный SMTP outcome отправляется на сверку без автоматического повтора.
- **Двойная отправка** блокируется: `legacy_event_reserved` проверяется при планировании и повторно непосредственно перед SMTP; старые `sent/sending/delivery_unknown` не перезаписываются.
- Локальные ошибки до SMTP повторяются не более 6 раз и с интервалом; это не делает платных запросов.
- `LaravelJourneyEventStore`, `LaravelJourneyContextProvider`, `LaravelJourneyHooks`, `DzJourneyMail`, `DzMailJourneyDrain`, Laravel migrations и конфигурация с **всеми флагами OFF по умолчанию**.

## Что нельзя считать выполненным

1. **Оригинальный пользовательский `DZ-Emails(1).zip` недоступен для чтения** при этой проверке; `copy-v1.proposed.json` наследует предложенные формулировки RC3, это не доказанный оригинальный архив. До совпадения/согласования нельзя включать живую отправку.
2. Нет полной приватной Laravel-копии в GitHub. Зависимости `vendor/`, актуальная staging БД, миграции и реальные обработчики checkout/teen-test в текущем репозитории не выполнялись. Все изменения в `review/`, а не в работающем `/var/www` или историческом `main`.
3. Конкретные вызовы `LaravelJourneyHooks::{completed,verifiedPayment,reportPublished}` должны быть вставлены в **один** доменный обработчик каждого события с выключением старого отправителя для новых сессий; точные места описаны в `docs/DEVELOPER_CUTOVER_AND_TEST_PLAN.md`.
4. Существующий `TeenApprovedMailDelivery::sendIfReady` пока остаётся авторитетным старым отправителем. Его нельзя подключать одновременно с новой готовностью. Для teen платных писем нужен независимый оплаченный receipt от текущего банковского callback.
5. 24-часовое обещание **включается только** после документированного подтверждения владельцем срока исполнения и автоматической эскалации при задержке. До этого отправляется честный сервисный статус без срока.
6. `dz_mail_marketing_consents` не заполняется автоматически по старому `allow_communications`: требуется действующая форма с подтверждаемым согласием. Исторические клиенты не получают новую маркетинговую рассылку.
